抽象层守护着每一个程序员的 SAN 值，我劝你不要深究
现代内存寻址实际上是 7D 的, 逻辑上变成 1D 是为了保护你可怜的大脑
你可以去写 Exapunks 的硬核汇编, 这玩意儿是真 2D 指令集, 脑袋没炸再往下看.
![](data:image/svg+xml;utf8,<svg%20xmlns='http://www.w3.org/2000/svg'%20width='1920'%20height='1080'></svg>)
* * *
现代内存 DRAM 寻址**简单来讲** 是一个 7 层架构:
Channel → Rank → Chip → Bank → Row → Column → Cell
如果写在教科书上可以说是 7 层, 但是实际你买到的内存每层里面还有更复杂的细分
![](data:image/svg+xml;utf8,<svg%20xmlns='http://www.w3.org/2000/svg'%20width='2048'%20height='1152'></svg>)
从中古时代开始 CPU 里面就集成了内存控制器。
老式的内存控制器只有一个控制单元，每次只能操作一个DIMM
后来增加了新的控制单元可以支持同时操作两个 DIMM
![](data:image/svg+xml;utf8,<svg%20xmlns='http://www.w3.org/2000/svg'%20width='1134'%20height='682'></svg>)
现在还有四通道, 八通道的内存控制器, 那就更牛逼了
通道多了，就可以同时访问更多的内存，DRAM 相对各级 Cache 延迟要高几个数量级，很多指令都是阻塞在等待内存完成, 这就是卡的根源。
**理论上** 双通道可以翻倍, 四通道可以翻四倍, 八通道可以翻八倍
**理论上** 多内核访问内存可以互不干扰, 牛逼的不行
**"理论上"** 三个字我劝你也别深究, 实际就是个玄学
* * *
DIMM（Dual Inline Memory Module，双列直插内存模块）就是你买到的内存条
DIMM 是在 SIMM（Single Inline Memory Module, 单列直插存储器模块）的基础上发展起来的
传统上来讲, SIMM 提供 32 位数据通道, 而 DIMM 则提供了 64 位的数据通道
![](data:image/svg+xml;utf8,<svg%20xmlns='http://www.w3.org/2000/svg'%20width='2048'%20height='1152'></svg>)
有了 DIMM 这层抽象以后下一层是 RANK 和 CHIP
DIMM 既然是双面的那就有两个 Physic Rank, 而 Chip 就是每个 Rank 上的内存颗粒
**物理上** 来讲是这样
**"物理上"** 这三个字你也别深究, 因为逻辑上不是这样的
* * *
下一层抽象是 BANK, 当然现代 DDR 丧心病狂的加入了 Bank Group
不过这个一般不单列为一层, 而且内部还有其他抽象层, 复杂度 Up Up
![](data:image/svg+xml;utf8,<svg%20xmlns='http://www.w3.org/2000/svg'%20width='1988'%20height='804'></svg>)
现代 CPU 与内存之间的接口位宽是 64bit，也就意味着 CPU 在一个时钟周期内会向内存发送或从内存读取 64bit 的数据。
可是，单个内存颗粒的位宽仅有 4bit、8bit 或 16bit。
因此，必须把多个颗粒并联起来，组成一个位宽为 64bit 的数据集合，才可以和 CPU 互连。
![](data:image/svg+xml;utf8,<svg%20xmlns='http://www.w3.org/2000/svg'%20width='2048'%20height='1152'></svg>)
生产商会把这样一个组合出的 64bit 集合称为一个 Logical Bank
* * *
每个 Bank 从**逻辑上** 来说是个 Memory Cell 的矩阵
**"逻辑上"** 三个字我劝你也别深究, 因为工艺上还有很多变种
![](data:image/svg+xml;utf8,<svg%20xmlns='http://www.w3.org/2000/svg'%20width='1868'%20height='935'></svg>)![](data:image/svg+xml;utf8,<svg%20xmlns='http://www.w3.org/2000/svg'%20width='1498'%20height='752'></svg>)
话说这玩意儿真的是二维寻址
现代内存做了很多优化, 这玩意儿几乎是个小 CPU
  * Bank Burst Mode


每次访问一个bit的时候，我们往往会把一横列的 bit 全部缓存到放大器中，最后只取一个进行输出, 太浪费了, 完全可以多取几个
我超, 小号 Cache Line
  * Bank Interleave


在对 Cell 进行读取之前，首先要满足 BitLine 预充电完毕，且电容的电荷重新充满电, 其实你可以按照顺序先给它们预充电
我超, 小号 Prefetch
还有很多类似的优化技术, 搞得这玩意儿非常像 CPU
甚至可以理解为指令集只有读, 预读, 批量读, 写入, 四个指令的 CPU
* * *
这里面一个个小格子**原则上** 来讲是 Bit Cell 门电路
**"原则上"** 三个字我劝你也别深究, 你买到的内存里是个什么鬼不好说
![](data:image/svg+xml;utf8,<svg%20xmlns='http://www.w3.org/2000/svg'%20width='751'%20height='430'></svg>)
DRAM 比较简单, 充满就是 1, 放电就是 0, 但是有个问题是会漏电, 得一直刷新.
刷新花费的时间和能量占比是随着 DRAM 的尺寸变大而几何式增加的。
实验显示, 当你买了 64G 的 DRAM 内存条时，几乎有一半的时间和能量都浪费在了刷新这件事情上。
* * *
除了 DRAM, 还有一种用在超高端内存上的 SRAM, 平常这东西一般用在高速缓存上
没有漏电问题, 非常灵敏且高速
![](data:image/svg+xml;utf8,<svg%20xmlns='http://www.w3.org/2000/svg'%20width='472'%20height='341'></svg>)
这是一个六管 SRAM Bit Cell, 假定存储的内容为1, 即在 Q 处的电平为高。
读周期，两根位线预充为逻辑 1, 随后 WL 充高电平，使得两个访问控制晶体管 M5 与 M6 通路。
接着保存在 Q 的值传递给 BL 预充的电位，并泻掉 ¬BL 预充的值。
BL 一侧，晶体管 M4 与 M6 通路，此时 VDD 所代表的逻辑 1, 如果存储的内容为0, 相反的电路状态将会使 ¬BL 为 1 而 BL 为 0。
![](data:image/svg+xml;utf8,<svg%20xmlns='http://www.w3.org/2000/svg'%20width='1080'%20height='475'></svg>)
只需要 ¬BL与 BL 有一个很小的电位差，读取的放大电路将会辨识出哪根位线是 1 哪根是 0。
而敏感度越高，读取速度就越快。
