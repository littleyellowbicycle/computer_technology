先讲个段子：
> 我去一家程序公司面试。  
> 面试官：你简历上说你心算速度非常的快，真的假的？  
> 我：当然，不信你出一道题！  
> 面试官：行，15乘以17等于多少？  
> 我：250。  
> 面试官：准确答案是255，你这算的不准！  
> 我：你别管准不准，你就说快不快吧！  
> 面试官：光快不准有啥用？  
> 我：抛开需求谈误差就是耍流氓。我面试的职位是图形图像开发，计算机上的像素灰度值范围是0到255。你能肉眼分辨出灰度值为250的像素和灰度值为255的像素吗？250和255，误差不到百分之二，完全在我的掌控之内。  
> 面试官：误差是会叠加的。一次运算的误差是百分之二，那么100次运算的误差叠加后是多少？假如一个产品有100个组件，每个组件的合格率是98%，那么这个产品被组装后的合格率只有10%。  
> 我：0.98的100次幂约等于0.132619555，你说合格率10%算的不准。  
>  面试官：0.98的100次幂，你怎么算的这么快？  
>  我：没算，我背的。  
> 面试官：抛开需求谈误差就是耍流氓。在这个语境下，合格率10%误差0.03不影响我的意思表达。  
> 我：合着，我误差百分之二不行，你误差百分之三十行？
我用这个段子表达三个道理：
**1.提高速度最简单的办法是牺牲精度。**
**2.提高速度最粗暴的办法是缓存查表。**
**3.缓存查表+插值拟合即牺牲精度又浪费存储，但是真快。**

再回到15*17这个问题，
15*17=(16-1)*(16+1) = 16*16 - 1 = 256 - 1 = 255
对于程序员来说，16*16根本不需要算，早就记录在大脑缓存中。
有些数学运算转化一下，就能提高效率，
比如幂运算：
我测试的10亿次powf运算的耗时是：21499(ms)
改用公式：pow(x,n) = exp(n*log(x))
return ::expf(n*::logf(x)); 10亿次运算的耗时是13089(ms)
但是有时会适得其反，
改用公式：pow(x,n) = exp2(n*log2(x))
return ::exp2f(n*::log2f(x)); 10亿次运算的耗时是134260(ms)
再比如双曲正弦，
下面是对双曲正弦函数的优化代码，并测试了自己机器上的耗时情况：

```
// 快速双曲正弦函数
inline float quick_sinh(float a)
{
#if 0
	return ::sinhf(a);					// 35907(ms) / 10亿
#if 0
	return (::powf(2.71828182846f, a) - ::powf(2.71828182846f, -a)) * 0.5f;	// 41603(ms) / 10亿
#elif 0
	return (::expf(a) - ::expf(-a)) * 0.5f;			// 9327(ms) / 10亿
#else
	float ea = ::expf(a);
	return (ea - 1.0f / ea) * 0.5f;				// 9166(ms) / 10亿
#endif
}
```

举个例子，优化开立方根的函数：
C语言中开立方根的函数为::cbrtf(x)，我测试它的耗时是：32721(ms)/10亿次
这个函数有个替代方式::powf(x, 0.3333333f)，于是有了优化代码：

```
inline float cuberoot(float x)
{
	if (x < 0.0f)
	{
		return -::powf(-x, 0.3333333f);
	}
	else
	{
		return ::powf(x, 0.3333333f);
	}
}
```

测试这个函数的性能耗时是：21263(ms)/10亿次，果然变快了，成就感满满，我真是个天才。
以我多年的经验，计算最快的方式是查表。
可惜查表的精度不够，那就查表+插值。
于是自己又写了一个基于查表后插值的开立方根函数，
先得生成一个2048大小的数组，用于存放[8, 1000]之间的立方根数值
// pow(x, 1/3) x ∈ [8, 1000]
static const float cuberoot_table_f32[2048] = {......};
表的大小是有限的，数值的大小是无限的，
所以需要将无限的数值映射到有限的表里。
用到了公式：cbrt(x) == 5*cbrt(x/125) == 0.2*cbrt(x*125)

```
float zmath::fast_cuberoot(float x)
{
	float s = 1.0f;
	if (x < 0.0f)
	{
		x = -x;
		s = -1.0f;
	}

	if (x < FLT_EPSILON)
	{
		return 0.0f;
	}

	// 将数值映射到[8, 1000)后再做插值运算
	// cuberoot(x) == 5*cuberoot(x/125) == 0.2*cuberoot(x*125)
	if (x < 8.0f)
	{
		do
		{
			x *= 125.0f;
			s *= 0.2f;
		} while (x < 8.0f);
	}
	else
	{
		while (x >= 1000.0f)
		{
			x *= 0.008f;		// 1/125
			s *= 5.0f;
		}
	}

	x = (x - 8.0f)*2.06350806f;		// 2047/992
	int index = (int)x;
	float fract = x - (float)index;
	return ((1.0f - fract)*cuberoot_table_f32[index] + fract*cuberoot_table_f32[index + 1]) * s;
}
```

测试它的性能与误差：

```

// abs(x) ∈[1000, 1000000]误差小于千分之5
// abs(x) ∈[1000000, 1000000000]误差小于0.025
```

再举个例子，浮点数乘除2的N次幂。
根据浮点数的存储方式，浮点数乘除2只需将其23~31的8个bit位加减1即可。
将浮点数运算改为加减运算，理论上显然能提高效率。

```
// 浮点数左移右移,以实现乘除2的n次幂

// n == 1	等价于: x*2
// n == -1	等价于: x/2
// n == 2	等价于: x*4
// n == -2	等价于: x/4
// n == 3	等价于: x*8
// n == -3	等价于: x/8
// 类似于C库函数float ldexpf(float x, int exp)和float scalbnf(float x, int exp)

// 耗时分析
// fast_shift比c标准函数::ldexpf和::scalbnf强，但不如直接相乘或相除
// ::ldexpf(z, -15);			// 21300(ms)/10亿次
// ::scalbnf(z, -15);			// 7661(ms)/10亿次
// fast_shift(z, -15);			// 1694(ms)/10亿次
// FLOAT_SHIFT(z, -15);			// 1684(ms)/10亿次
// z * 0.000030517578125f;		// 760(ms)/10亿次
// z / 0x8000;				// 757(ms)/10亿次
// z / 32768.0f;			// 753(ms)/10亿次
// z / ((float)RAND_MAX + 1);		// 756(ms)/10亿次
// z / (RAND_MAX + 1.0f);		// 759(ms)/10亿次

union FloatInt
{
	float fVal;
	int iVal;
};

// 返回x乘以2的n次幂(x*(2^n))
inline float fast_shift(float x, int n)
{
	FloatInt k;
	k.fVal = x;
	if (k.iVal & 0x7fffffff)			// 判断0
	{
		int b = ((k.iVal >> 23) + n) & 0xff;	// 阶码位+n
		k.iVal &= 0x807fffff;			// 抹去阶码位，保留符号位和尾数位
		k.iVal |= (b << 23);
	}
	return k.fVal;
}

#define FLOAT_SHIFT(x, n) \
	( [](float _x, int _n) \
		{ \
			int k = *(int*)(&_x); \
			if (k & 0x7fffffff) \
			{ \
				k = (k & 0x807fffff) | ((((k >> 23) + (_n)) & 0xff) << 23); \
			} \
			return (*(float*)&k); \
		} \
		(x, n) \
	)
```

WTF靠，优化了个寂寞。

```
::ldexpf(z, -15);

z / 32768.0f;

```
