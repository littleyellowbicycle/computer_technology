### 0.GUP硬件模型
如下图所示, CPU一般只有少量(100个以下)的核心, 而GPU一般拥有大量的核心(1000个以上).
目前常用的计算机架构都是储存结构计算机, 即冯诺依曼架构计算机. 
冯诺依曼架构计算机的运行逻辑是计算核心(CPU或者CUDA Core)从内存(DRAM)中取数据和指令, 进行计算, 计算完毕后放回内存空间.
但经过几十年的发展, CPU的速度已经变得非常快速, 而内存的速度进步缓慢, 这导致CPU大量时间在等待内存提交数据, 浪费了大量时间. 因此, 我们设计了缓存Cache来缓解内存和CPU之间的数据差异. 
**CPU的硬件架构是 CPU- >Core 这样的层级关系**
其中, 现代CPU有多个核心, 每个核心都有自己独立的数据寄存器, 指令寄存器和控制器每个核心都拥有自己的L1 Cache和L2 Cache, 共用L3 Cache. 

```
CPU
├── Core 0
│     ├── L1 Cache
│     ├── Control
├── Core 1
│     ├── L1 Cache
│     ├── Control
└── L3 Cache & Memory
```

**GPU的硬件架构是 GPU- >SM->CUDA Core 这样的层级关系**
对于GPU来说, 因为核心太多, 所以多个CUDA Core归为一个Streaming Multiprocessors(SM)管理. 右图中绿色的小块就代表一个CUDA Core, 而一行代表一个SM.
![](https://pic1.zhimg.com/v2-5b6c561edd5eec4a5a376a39ca7cb9b8_1440w.jpg)
对于一个SM来说, 其拥有自己的Shared Memory, 这个共享内存可以让该SM里面的所有Core访问. 
对于一个Core来说, 其拥有自己的数据寄存器和程序计数器PC, 但没有指令寄存器. 因此, 可以粗略地认为一个SM里面的所有Core执行的是相同的指令(为什么是粗略的, 后面在软件中会讲)
对于一个Core来说, 其可以访问的内存空间有, 自己的数据寄存器, 所属SM的Shared Memory, 板载内存(也就是显存). 从速度上来说, 肯定是寄存器最快, 然后是共享内存, 然后是板载内存. 

```
GPU
├── SM 0 (Streaming Multiprocessor)
│     ├── CUDA Core Array
│     │      ├── CUDA Core
│     │              ├── Register
│     ├── Shared Memory & L1 Cache
│     ├── Control
├── SM 1 (Streaming Multiprocessor)
│     ├── CUDA Core Array
│     │      ├── CUDA Core
│     │              ├── Register
│     ├── Shared Memory & L1 Cache
│     ├── Control
└── SM 2
└── ...
└── Global Memory & L2 Cache
```

### 1.CUDA软件模型
硬件对程序员来说是透明的, 意思是不可见的. 一般来说, 程序员只需要考虑软件部分的实现就行. 但对于CUDA程序员来说, 要设计出高性能的CUDA程序, 又必须考虑软件在硬件上的执行. 
前面提到, GPU的硬件架构是 GPU->SM->CUDA Core 这样的层级关系, 而软件上我们也有类似但不相同的层级. 
为了方便解释, 我们先参考CPU的软件模型. 
很明显, CPU的软件模型是
Process->Thread
即一个进程管理多个线程, 这个不用再讲了吧
而GPU的软件模型就会非常地复杂

```
Process
├── CPU Code
│     ├── Thread 0 
│     ├── Thread 1
├── GPU Code
│     ├── Grid
│     │     ├──Thread Block 0
│     │     │    ├── Warp 0
│     │     │    │    ├── Thread 0
│     │     │    │    ├── Thread 1
│     │     │    │    ├── Thread 2
│     │     │    │    ├── ...
│     │     │    │    ├── Thread 31
│     │     │    ├── Warp 1
│     │     │    ├── ...
│     │     ├──Thread Block 1
│     │     ├── ...
```

可以看见, 对于GUP程序来说, GPU程序有CPU执行的部分和GPU执行的部分. 
其中, CPU执行的部分用`__host__`定义, GPU执行的部分用`__global__`, 或者`__device__`定义. 如果一个函数或者变量没有定义, 则默认 `__host__`. 
那`__global__`和 `__device__`有什么区别呢? 
`__global__`函数声明的是核函数, 即Kernel Function, Kernel Function会分配到GPU的每一个线程上执行.
Kernel Function可以调用`__device__`函数或者变量, 但不允许调用`__host__`函数或者变量, 因为CPU和GPU物理上相隔非常远, 数据过不来. 
如下所示便是Kernel Function的定义和调用方式. 
![](https://picx.zhimg.com/v2-06478f07f35cfbfaf0193474be23d931_1440w.jpg)![](https://pic3.zhimg.com/v2-34268bb3cf02ea5ceb2494716ee93a52_1440w.jpg)
明显可以看出`(ResultDataCUDA,threadDataAddress,baseSeed)`是核函数的3个传入参数, 那`GRID__SIZE,BLOCK_SIZE`是什么? 
`GRID__SIZE`是Grid的大小. `BLOCK_SIZE`是 Thread Block 的大小. 
那Grid和Thread Block又是什么? 
参考前面提到的GPU硬件模型, 一块GUP有多个SM, 比如说4060就有8个SM, 而一个SM又有一个CUDA Core Array, 一个CUDA Core Array又有很多CUDA Core.
软件最终还是需要硬件来运行, 而GPU程序的每一个线程, 最终都得一个CUDA Core来执行. 
但是GPU上面的线程实在是太多了, 如果按照CUDA Core为单位管理, 那4060这种入门级显卡都有3072个线程. 
参考GPU的硬件模型, 一个SM只有一个控制器, 整个SM里面的所有CUDA Core执行的是同一条指令. 因此, 我们需要对线程进行分块管理. 
在一个SM里面, 必须要对多个线程进行统一调度, 才能保证这些线程在同一时间执行的是同一条指令. 
这个线程调度的基本单位叫Warp, 一个Warp里面包含32个线程. 
不过一个SM里面可远不止32个CUDA Core, 因此, 合并多个Warp成一个Thread Block可以充分利用SM的性能. 
GPU里面可不止一个SM, 因此, 合并多个Thread Block成一个Grid可以充分调用GPU的性能.
因此, 在软件方面, CUDA的架构如下. 
GPU Device->Grid->Thread Block->Warp->Thread
这样一来, 我们便可以将GUP的软件和硬件对应起来. 如下图所示.

### 2.CUDA代码简单介绍
最简单的CUDA代码包括4部分
  1. 申请GPU和CPU内存(非必须)
  2. 从CPU内存拷贝数据到GPU内存(非必须)
  3. 执行`__global__`函数
  4. 从GPU内存拷贝结果到CPU内存(非必须)


前面提到, CUDA分为CPU执行的部分和GPU执行的部分, 其中, CPU执行的部分用`__host__`定义, GPU执行的部分用`__global__`, 或者`__device__`定义. 如果一个函数或者变量没有定义, 则默认 `__host__`
`__global__`将会分配给每一个CUDA线程, 所以是每个线程都执行的函数. 
`__global__`函数为`void`类型, 注意不是`void*`, 必须是`void`
那我们要怎么接受 `__global__`函数的计算结果呢? 很简单, 直接进行内存拷贝. 
假设我们的`__global__`有如下定义:
`data`是我们的数据, `result`是我们数据经过GPU处理之后的结果. 
![](https://picx.zhimg.com/v2-b3cd761a92240fefe071fc034daa9973_1440w.jpg)
前面提到, 因为GPU和CPU物理距离很远. GPU不可以访问CPU的内存数据. 因此, `__global__`函数的`data`和`result`数组都必须是GPU的内存数组. 
利用`cudaMalloc`可以申请GPU内存, 利用`cudaMemset`可以对GPU内存进行初始化, 利用`cudaMemcpy`可以对数据在GPU和CPU之间拷贝.
`cudaMalloc`函数声明如下, 传入地址和内存大小申请GPU内存.
`__host__ ​__device__​ cudaError_t cudaMalloc(void** devPtr, size_t size)`
![](https://pic3.zhimg.com/v2-ffe1da136278518bea3f349f1bf19de4_1440w.jpg)
`cudaMemcpy`函数声明如下, 
`__host__ cudaError_t cudaMemcpy(void* dst, const void* src, size_t count, cudaMemcpyKind kind)`
`cudaMemcpyKind`是`enum`类型, 包括
  * 0, `cudaMemcpyHostToHost`
  * 1, `cudaMemcpyHostToDevice`
  * 2, `cudaMemcpyDeviceToHost`
  * 3, `cudaMemcpyDeviceToDevice`
  * 4, `cudaMemcpyDefault`


从CPU(`__host__`)到GPU(`__device__`)该参数填`cudaMemcpyHostToDevice`
从GPU(`__device__`)到CPU(`__host__`)该参数填`cudaMemcpyDeviceToHost`

### 4.本文的代码的性能问题
虽然本文的GPU代码比CPU代码快很多, 但我对这个性能实际上是非常不满意的. 本文的GPU代码主要有以下性能问题.
1.4060不适合64位整数运算
我的随机引擎会大量进行64位整数的运算, 这在CPU上不是问题, 但对于4060来说, 64位整数运算比32位慢很多. 
CUDA其实有自己的随机引擎, **`cuRAND`**, 不过我没有测试过其性能和随机数质量. 等有时间再测试.
下图所示是4060的SM的结构图. 可以看到, 并没有专门的计算64位整数的硬件. 这意味着64位整形的计算必然会被翻译成多条机器指令, 比32位整形慢很多.
![](https://pic1.zhimg.com/v2-8ecb16d6f62156595de04385bd5efe20_1440w.jpg)
下图所示是来自 [@Edison Chen](https://www.zhihu.com/people/24847e390af41e01886d67db285960da) 的4060各指令测试性能. 
![](https://pic3.zhimg.com/v2-81afe205fda8a40dbb882fe8d301b5ae_1440w.jpg)
2.GPU完全没有分支预测
GPU不同于CPU, 因为SM的控制电路非常小. 
GPU中线程按照Warp调度, 一个Warp先执行所有`if`为真的线程, 再执行所有`if`为假的线程. 
而蒙特卡洛过程中有非常多的逻辑判断, 所以会极大影响性能.

    	myResult[index]=myResultData+index*MAX_PULL_COUNT;
    }

    unsigned pullCount=0;
    unsigned pullCountUP=0;
    unsigned afterglowCoral=0;
    unsigned _3StarHit=0;
    bool mustFeatured5Star=false;
    for(long long unsigned int indexRepeat=0;indexRepeat<myRepeatTimes;indexRepeat=indexRepeat+1){
        pullCount=pullCount+1;
        unsigned random=PCG32Uniform_Strict(&PCGStatus,0,BaseMod-1);
        if(random<_5StarRate[pullCount]){
            pullCountUP=pullCountUP+pullCount;
            if((random&1)||mustFeatured5Star){
                get5StarFeatured(&mustFeatured5Star,&_3StarHit,&afterglowCoral);
                writeResult(myResult,&history,&pullCountUP,&afterglowCoral);
            }else{
                get5StarNotFeatured(&mustFeatured5Star,&_3StarHit,&afterglowCoral);
            }
            pullCount=0;
        }else{
            if(random<Base4StarRate){
                get4Star(&_3StarHit,&afterglowCoral);
            }else{
                if(_3StarHit==Max3StarCount){
                    get4Star(&_3StarHit,&afterglowCoral);
                }else{
                    _3StarHit=_3StarHit+1;
                }
            }
        }
    }
}

 /**
 * Description:
 * 
 * PCG32 CUDA version.
 * 
 * Head only pseudorandom engine base on PCG-XSH-RR, 
 * high performance, statistically good and easy to use.
 * 
 * Functions:
 * 
 * Set the seed of PCG random engine and initlize 
 * void PCG32SetSeed(PCG32Struct* status,long long unsigned int seed);
 * 
 * Generate a unsigned type random number in range of [0,0xFFFFFFFF(4294967295)]
 * unsigned PCG32(PCG32Struct* status);
 * 
 * Generate a unsigned type random number that obey uniform distrubution in range of [min,max]
 * unsigned PCG32Uniform(PCG32Struct* status,unsigned min,unsigned max);
 * 
 * Generate a double type random number that obey uniform distrubution in range of [min,max]
 * double PCG32UniformReal(PCG32Struct* status,double min,double max);
 * 
 * Generate a double type random number that obey standard normal distrubution
 * double PCG32StandardNormal(PCG32Struct* status);
 * 
 * Example:
 * 
 * PCG32Struct PCGStatus;
 * PCG32SetSeed(&PCGStatus,time(NULL));
 * double random=PCG32UniformReal(&PCGStatus,-1,999);
 * 
 * Note:
 * 
 * Remember to set the seed.
 * Use its own PCG32Struct in each thread function and set different seed. 
 * 
*/

#ifndef __PCG32_CUDA_H__
#define __PCG32_CUDA_H__

#ifdef __cplusplus
extern "C"{
#endif

/**
 * warning: #warning "math_functions.h is an internal header file and must not be used directly.  
 * This file will be removed in a future CUDA release.  
 * Please use cuda_runtime_api.h or cuda_runtime.h instead." [-Wcpp]
 * */
#include <cuda_runtime_api.h>

__device__ static long long unsigned int const multiplier=6364136223846793005LLU;
__device__ static long long unsigned int const increment=1442695040888963407LLU;
__device__ static long long unsigned int const PCG32Max=0x00000000FFFFFFFFLLU;
__device__ static const unsigned char PCG32False=0;
__device__ static const unsigned char PCG32True=1;
__device__ static const double PCG32RealScale=(double)1/(double)PCG32Max;

typedef struct _PCG32Struct{
	long long unsigned int state;
	long long unsigned int seed;
	double normalDistributionSaved;
	unsigned normalDistributionSavedValid;
}PCG32Struct;

__device__ static inline unsigned rotr32(unsigned x,unsigned r){
	return x>>r|x<<(-r&31);
}

__device__ static inline unsigned PCG32(PCG32Struct* status){
	long long unsigned int x=status->state;
	unsigned count=(unsigned)(x>>59);
	status->state=x*multiplier+increment;
	x=x^(x>>18);
	return rotr32((unsigned)(x>>27),count);
}

__device__ static inline unsigned PCG32Uniform(PCG32Struct* status,unsigned min,unsigned max){
	if(min>max){
		unsigned tempory=max;
		max=min;
		min=tempory;
	}
	long long unsigned int gap=max-min+1;
	if((gap&(gap-1))==0){
		return (PCG32(status)&(gap-1))+min;
	}
	unsigned range=(unsigned)(((PCG32Max+1)/gap)*gap);
	unsigned random=PCG32(status);
	while(random>range){
		random=PCG32(status);
	}
	return (random%gap)+min;
}

// max can not smaller than min and gap can not be power of 2
__device__ static inline unsigned PCG32Uniform_Strict(PCG32Struct* status,const unsigned min,const unsigned max){
	unsigned gap=max-min+1;
	unsigned range=(unsigned)(((PCG32Max+1)/gap)*gap);
	unsigned random=PCG32(status);
	while(random>range){
		random=PCG32(status);
	}
	return (random%gap)+min;
}

// max can not smaller than min
__device__ static inline unsigned PCG32Uniform_MaxBiggerThanMin(PCG32Struct* status,const unsigned min,const unsigned max){
	long long unsigned int gap=max-min+1;
	if((gap&(gap-1))==0){
		return (PCG32(status)&(gap-1))+min;
	}
	unsigned range=(unsigned)(((PCG32Max+1)/gap)*gap);
	unsigned random=PCG32(status);
	while(random>range){
		random=PCG32(status);
	}
	return (random%gap)+min;
}

__device__ static inline double PCG32UniformReal(PCG32Struct* status,double min,double max){
	return min+((double)PCG32(status))*PCG32RealScale*(max-min);
}

__device__ static inline double PCG32StandardNormal(PCG32Struct* status){
	if(status->normalDistributionSavedValid){
		status->normalDistributionSavedValid=PCG32False;
		return status->normalDistributionSaved;
	}
	double u1,u2,S;
	do{
		u1=(double)(PCG32(status))/(double)PCG32Max*2.0-1.0;
		u2=(double)(PCG32(status))/(double)PCG32Max*2.0-1.0;
		S=u1*u1+u2*u2;
	}while(S>1.0||S==0.0);
	const double toMultiple=sqrt(-2.0*log(S)/S);
	status->normalDistributionSavedValid=PCG32True;
	status->normalDistributionSaved=toMultiple*u2;
	return toMultiple*u1;
}

__device__ static inline void PCG32Init(PCG32Struct* status){
	status->state=status->seed+increment;
	status->normalDistributionSavedValid=PCG32False;
	PCG32(status);
}

__device__ static inline void PCG32SetSeed(PCG32Struct* status,long long unsigned int seed){
	status->seed=seed;
	PCG32Init(status);
}

	const unsigned tempory=array[index0];
	array[index0]=array[index1];
	array[index1]=tempory;
}

	if(length<2){
		return;
	}
	for(long long unsigned int index=0;index<(length-1);index=index+1){
		unsignedSwap(array,index,PCG32Uniform_MaxBiggerThanMin(status,index,length-1));
	}
}
