分享几个我觉得真正有深度的，不是那种”知道了用不上”的花活。
* * *
**Linux的job control，大多数人只会`ctrl+c`**
你在终端跑一个命令，`ctrl+c`杀掉，`&`放后台，这些大家都会。但Linux的任务控制远不止这些。
`ctrl+z`把进程挂起，进程没死，只是暂停了。这时候你可以：
  * `fg` 恢复到前台继续跑
  * `bg` 扔到后台继续跑
  * `jobs` 看当前shell里有多少挂起/后台的任务


但这里有个坑：**这些任务都绑在当前shell上，你关掉终端它们就死了** 。
所以有了`nohup`和`disown`：
  * `nohup command &` 一开始就让进程脱离终端
  * `disown %1` 让已经在跑的后台任务脱离终端


实际场景：你ssh到服务器跑了个脚本，跑到一半发现要很久，但你想断开ssh回家。`ctrl+z`挂起，`bg`扔后台，`disown`脱离终端，然后安心断开。明天来了`ps aux | grep xxx`找到它，还在跑。
这不是什么花活，是真正理解Linux进程管理的基础。
* * *
**`/proc`和`/sys` 不是普通目录，是内核的窗口**
很多人知道`/proc`下面有进程信息，但不知道这东西有多强大。
`/proc/<pid>/fd/` 这个目录里是进程打开的所有文件描述符。线上排查问题的时候，想知道一个进程在读写哪些文件、连着哪些socket：

```
ls -la /proc/<pid>/fd/
```

`/proc/<pid>/maps` 是进程的内存映射，能看到它加载了哪些动态库，内存布局是什么样的。
`/proc/<pid>/environ` 是进程的环境变量，想知道一个运行中的进程用的什么配置：

```
cat /proc/<pid>/environ | tr '\0' '\n'
```

还有`/proc/sys/`下面全是内核参数，可以直接读写。比如：

```
# 看当前系统最大文件描述符数
cat /proc/sys/fs/file-max

# 临时改掉（重启失效）
echo 1000000 > /proc/sys/fs/file-max
```

这些不是”奇技淫巧”，是Linux的基础设施。但大多数人用了几年Linux都不知道。
* * *
**`strace`，排查诡异问题的终极武器**
程序行为诡异，日志看不出来，不知道它在干什么？`strace`能看到进程的所有系统调用。

```
strace -p <pid>
```

挂上去，进程干的每一件事你都能看到：读了什么文件、写了什么数据、连了什么网络、等了什么锁。
实际场景：有个服务启动很慢，日志就一行”starting…“然后卡住。`strace`一挂，发现卡在`connect()`，在等一个连不上的Redis。配置文件里写的Redis地址是错的。

```
# 跟踪特定类型的系统调用
strace -e open,read,write -p <pid>

# 跟踪网络相关
strace -e network -p <pid>

# 统计每种系统调用的耗时
strace -c -p <pid>
```

`strace -c`特别有用，能统计进程把时间花在哪类系统调用上，是CPU计算还是IO等待，一目了然。
* * *
**`/dev/shm`不只是快，是内存文件系统**
很多人知道`/dev/shm`读写快，因为是内存。但不知道它真正的用途。
这是一个tmpfs，挂载在内存上的文件系统。它的特点：
  * 读写速度是内存速度，比SSD快一个数量级
  * 重启就没了，适合放临时数据
  * 默认大小是内存的一半，可以通过`mount -o remount,size=4G /dev/shm`调整


实际场景：你要处理一个10GB的日志文件，用`awk`/`sed`处理完再写回去。如果在机械硬盘上操作，光IO就要几分钟。把文件拷到`/dev/shm`里处理，几秒钟搞定。

```
cp huge_log.txt /dev/shm/
cd /dev/shm
awk '{print $1}' huge_log.txt > result.txt
mv result.txt /home/xxx/
```

但要注意，这玩意占的是内存，别把内存撑爆了。
还有个类似的`/tmp`，很多发行版也是tmpfs，但有些不是，具体看`df -h /tmp`。
* * *
**`lsof`，找出”谁在用这个文件/端口”**
删除文件后磁盘空间没释放？因为还有进程在用它。

```
lsof | grep deleted
```

找到是谁，kill掉或者重启它，空间就释放了。
端口被占用了，不知道是谁？

```
lsof -i :8080
```

想看某个进程打开了哪些文件和网络连接？

```
lsof -p <pid>
```

这个命令用得好，能省很多排查时间。
* * *
**`awk`单行命令，替代一百行Python**
很多人觉得`awk`难学，其实记住一个模式就够用了：

```
awk '{print $1}' file.txt      # 打印第一列
awk -F',' '{print $2}' file.csv # 按逗号分隔，打印第二列
awk '$3 > 100 {print $0}' file.txt  # 第三列大于100的行
awk '{sum += $1} END {print sum}' file.txt  # 求和
```

实际场景：线上日志，想统计每个IP的访问次数：

```
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -20
```

这一行顶你写二十行Python。
`awk`的精髓是**按行处理，按列提取** ，记住这个，90%的场景够用了。
* * *
这些不是花活，是真正理解Linux的基础。会用`strace`排查问题的人，和只会看日志的人，解决问题的效率差几个档次。
我见过太多人用了五六年Linux，还停留在`cd`、`ls`、`cat`的水平，出了问题就只会重启。把这几个工具用熟，你会发现Linux比你想象的透明得多。
