# 内存为何不是二维寻址：DRAM 的多层抽象

## 核心结论
> 现代内存的寻址其实是 7 层架构（Channel → Rank → Chip → Bank → Row → Column → Cell），之所以在逻辑上呈现为一维线性地址，是为了保护程序员的大脑。Bank 内部的存储单元矩阵确实是二维结构，但叠加了 Bank Burst Mode、Bank Interleave 等优化后，DRAM 几乎像一台只有读/预读/批量读/写四条指令的简易 CPU，强行二维寻址既无必要也无法突破现有多层抽象。

## 内存的"七维"真相

很多人以为内存是一根扁平的地址线，顺序排列字节即可。但实际上现代 [[DRAM]] 的寻址是一个 **7 层架构**：

- **Channel**（通道）：CPU 集成[[内存控制器]]后，多通道可并行访问多个 DIMM，双通道理论带宽翻倍、四通道翻四倍、八通道翻八倍。
- **Rank**（物理 Rank）：DIMM 双面有两个 Rank。
- **Chip**（内存颗粒）：每个 Rank 上的颗粒。
- **Bank**（逻辑 Bank）：为凑齐 CPU 的 64bit 数据位宽，需要把多个 4/8/16bit 的颗粒并联为一个 Logical Bank。现代 [[DDR]] 还引入 Bank Group 进一步分组。
- **Row / Column / Cell**：Bank 内部用行/列地址选中具体的存储单元。

所以问题"为什么不设计成二维寻址"本身就预设了一个错误前提——内存从来不是一维的，而是七维的；逻辑地址把多维折叠成一维，只是为了不让程序员当场爆炸。

## Bank 内部确实是二维的

在 Bank 这一层，存储单元确实是一个 Memory Cell 的矩阵，即真正意义上的二维[[寻址]]：

- **行选通**后读出整行到放大器（Sense Amplifier）。
- **列选通**挑出其中需要的几位。

但这里已经做了大量优化，让 Bank 看起来像一台小 CPU：

- **Bank Burst Mode**：一次预充电就把整行都读到放大器，何必只取一个？这就是小号 [[Cache Line]]。
- **Bank Interleave**：趁预充电的空档切换 Bank 工作，做到了小号 [[Prefetch]]。
- 配合刷新、预充电、突发传输等机制，DRAM 行为更接近"只有读、预读、批量读、写四条指令的 CPU"。

## DRAM 与 SRAM 的权衡

- **[[DRAM]]**：每个 Bit Cell 就是一个电容 + 一个晶体管，结构简单、密度高，但会漏电，需要持续刷新。64GB 内存条上刷新消耗的时间和能量可达近一半。
- **[[SRAM]]**：六管结构，无漏电、灵敏高速，但密度低、成本高，只用于 [[Cache]]（如寄存器文件、L1/L2/L3）。

## 抽象层保护了谁

从内存条 → DIMM → Rank → Chip → Logical Bank → Cell，每一层都有"原则上""物理上""逻辑上""理论上"的字眼需要深究。作者的结论很直白：**抽象层守护着每一个程序员的 SAN 值**。如果真想打穿所有抽象层去微操 Bit Cell，请先玩一玩 [[Exapunks]] 的硬核汇编，脑袋没炸再继续。

## 一句话总结

内存不是"被设计成一维"，而是本来就有七维；Bank 内部早已在二维寻址，但中间隔着六层硬件抽象与优化，外部再叠加一层二维寻址只会徒增复杂度而无实际收益。列式存储把同一列连续排列，正是对这些底层特性的工程化利用。
