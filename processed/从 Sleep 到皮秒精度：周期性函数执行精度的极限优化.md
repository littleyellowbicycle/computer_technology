# 从 Sleep 到皮秒精度：周期性函数执行精度的极限优化

## 核心结论
> 在通用操作系统下用 [[Sleep函数]] 实现精确周期性调用误差可达 100% 以上，根本原因是 [[线程调度]] 引入了不可控延迟。作者通过六步迭代——替换为 [[忙等待]]、迁移到 [[Zynq]] 裸机、自研编译器、自研 CPU、引入 [[恒温晶振]] 与 [[PPS信号]] 驯钟——将 5ms 间隔的执行偏差从毫秒级压缩到皮秒级，证明在软硬件全栈自研时精度极限取决于物理时钟而非软件栈。

## 详细内容
## 核心结论
在通用操作系统下用 [[Sleep函数]] 实现精确周期性调用误差可达 100% 以上，根本原因是 [[线程调度]] 引入了不可控延迟。通过六步迭代——替换为 [[忙等待]]、迁移到 [[Zynq]] 裸机、自研编译器、自研 CPU、引入 [[恒温晶振]] 与 [[PPS信号]] 驯钟——可将 5ms 间隔的执行偏差从毫秒级压缩到皮秒级，证明在软硬件全栈自研时精度极限取决于物理时钟而非软件栈。

## 问题背景
目标是在 C/C++ 中稳定地每隔 5ms 执行一次函数，例如 `for(int i=0;i<100;i++){ Sleep(5); function(); }`。在通用操作系统中，由于线程调度、上下文切换等不可控因素，单纯的 `Sleep` 难以达到稳定精度。

## 阶段一：Sleep 的缺陷
`Windows Sleep(5)` 实际延迟可达 10–15ms，偏差率 100%–200%。原因在于 `Sleep` 会触发 [[线程调度]]，下一次时间片轮回到当前线程的时刻不可控。

## 阶段二：忙等待轮询
使用 [[忙等待]] 轮询替代 `Sleep`：

```c
px_uint lasttime = PX_TimeGetTimeUs();
for (int i = 0; i < 100; i++) {
    while (1) {
        px_uint now = PX_TimeGetTimeUs();
        if (now - lasttime >= 5000) {
            power_switch();
            lasttime = now;
            break;
        }
    }
}
```

多数情况下偏差压缩到亚毫秒级，但主线程时间片耗尽后仍会被 OS 切换，残留偶发毫秒级抖动。提高进程优先级可缓解但无法根治。

## 阶段三：消灭操作系统（Zynq 裸机）
硬件平台选用 [[Zynq]] XC7Z020 SoC，在 [[Vivado]] 中完成三步配置：
1. 配置 Processing System（CPU 与 DDR）；
2. 将 PL 时钟设为 100MHz 作为计时基准；
3. 用 FPGA 搓一个 [[AXI Lite]] 总线可访问的 32 位自增计数器。

在 [[Vitis]] 下创建 Standalone（无 OS）工程后，使用相同忙等待逻辑读取硬件计数器。最终偏差 ≈ 90ns，相对误差约 0.002%。

## 阶段四：消灭编译器
继续提升频率收益递减，访存与总线仲裁引入新的抖动。作者决定进一步自研编译器（[[PainterEngine]] 内置的编译前端），将 C 代码编译为自定义 IR / 指令流，并由 FPGA 直接执行。这样可消除编译器优化与指令延迟的不可控因素。

## 阶段五：消灭 CPU
为极致可控，直接在 FPGA 上用 Verilog 搓一个极简的哈佛结构 [[微控制器]]：
- 寄存器：`IP`、`BP`、`SP`、`R1`
- 内存：仅 128 字节指令空间 + 堆栈
- 指令集：6 条定长指令（PUSH、MOV、INV、POP、RET 等）
- `RET` 指令直接内置 5ms（500000 个 50MHz 周期）硬延迟

仿真结果显示执行间隔几乎完美对齐 5ms。误差仅来源于：
- 信号上升沿抖动
- [[晶振]] 的 PPM 误差

50MHz 普通晶振约 10ppm，每秒误差约 0.00001%，折算到 5ms 约 500ps；若改用 [[恒温晶振]]（百 MHz 误差 0.1ppm），可降至约 5ps。

## 阶段六：PPS 驯钟（2025 年二更）
进一步引入 GPS 的 [[PPS信号]] 作为外部参考，构建[[时钟驯服]]模块：
1. 用 [[MMCM]] 或 [[PLL]] 将输入时钟倍频到远高于目标频率（如 1kHz 目标 → 1MHz 输入）；
2. 在 PPS 上升沿后第一个输入时钟内采样上一秒的实际脉冲数（规避 [[亚稳态]]）；
3. 通过调节输出脉冲宽度补偿累计偏差，并把误差分散到下一秒的全部脉冲中（避免局部过载）；
4. 加入 `stable` 状态机：PPS 连续稳定 8 秒才进入锁定，单次丢失则退出。

效果：以 100MHz 输入、10MHz 输出、50ppm 输入误差为例，500ns 误差被分散到 1 秒的 200 个 5ms 样本中，单次偏差可压缩到 2–3ps 级别。

## 为什么不用中断？
中断延迟在工程上更实用，但仍存在数个时钟周期的抖动（注意是抖动而非相位偏差），其来源与 CPU 流水线、抢占时序密切相关，无法达到自研 CPU + 驯钟方案的皮秒级精度。

## 总结与边界
精度演进路径：Sleep → 忙等待 → 裸机 FPGA → 自研编译器 → 自研 CPU → PPS 驯钟，从毫秒级一路压缩到皮秒级。继续突破将进入工艺与材料等物理层面的限制。
