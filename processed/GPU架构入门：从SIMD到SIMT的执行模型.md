# GPU架构入门：从SIMD到SIMT的执行模型

## 核心结论
> GPU本质是SIMD机器，但编程采用SPMD模型，硬件动态将执行同指令的线程合并为Warp，从而形成特有的SIMT执行模型。理解编程模型与执行模型的分离，是把握SIMD→SPMD→SIMT三层映射的关键；GPU通过大量简单核心堆叠、FGMT隐藏访存延迟、Warp时空双重并行实现远超CPU的吞吐量。

## 详细内容
## 1. 编程模型与执行模型的分离

理解 GPU 架构的第一道关卡，是区分两个常被混淆的概念：

- **[[编程模型]]**：程序员如何表达代码（[[SISD]]/[[SIMD]]/[[SPMD]]/多线程等）。
- **[[执行模型]]**：硬件实际如何执行（乱序、向量、脉动阵列等）。

二者可以完全不同：程序员写的是冯诺依曼顺序代码，硬件可能用乱序执行；程序员写 SPMD 代码，硬件可能用 SIMD 实现。搞清这一层，才不会把软件视角与硬件视角混为一谈。

## 2. 从 SIMD 到 SIMT：三层映射

GPU 处于 SIMD 的集大成位置，但它对外暴露的编程界面不是 [[SIMD]] 编程，而是 [[SPMD]] 编程——程序员写一段核函数，指定线程数 N，硬件负责把 N 次"迭代"映射到物理资源上。

具体的对应关系如下：

| 层次 | 概念 | 角色 |
|---|---|---|
| 编程模型 | SPMD | 程序员视角：每个线程独立上下文，执行同一段代码 |
| 执行模型 | SIMT | 硬件视角：动态把线程合并为 [[Warp]]，按 SIMD 方式发射 |
| 硬件本质 | SIMD | Warp 内部的指令与数据通路仍是 SIMD |

一句话总结：**SPMD 编程 + SIMD 硬件 = SIMT 执行**。

### 与传统 SIMD 的关键差异

- 传统 SIMD 只有单一线程，指令严格同步，软件必须知道向量长度（VLEN）；
- 基于 Warp 的 SIMD 中，多线程以 SIMD 方式执行但不必同步（32 个线程可以分批进入流水线），软件不需关心 VLEN，线程可被灵活分组成 Warp；
- 指令集架构本身是标量的，由硬件动态形成 SIMD 操作。

## 3. Warp 的执行机制

[[Warp]] 是 GPU 的基本调度单位，通常包含 32 个线程。其执行结合了 [[Vector Processor]] 与 [[Array Processor]] 的思想：

- **空间并行**：多个 [[Lane]]（功能单元）同时处理不同线程的同一阶段；
- **时间并行**：同一 Lane 在不同周期处理同一 Warp 的不同线程批次，流水化推进。

一个典型执行序列：第 0 周期把 Warp0 的线程 0–7 送入 Load 流水线入口；第 1 周期把线程 8–15 送入，同时 Warp0 在流水线内推进一级，并取 Warp1 进入 Mul 单元。以此类推，实现多 Warp、多指令单元的交织。

## 4. FGMT：细粒度多线程隐藏延迟

[[FGMT]]（Fine-Grained Multithreading）每个周期切换不同 Warp，目的只有一个：**不让硬件空转**。当某 Warp 因 Load Miss 卡住时，立刻让别的 Warp 顶上去执行。核心思想与标量流水线处理数据依赖完全一致——数据没到就先干别的。

变体还包括只切换"准备就绪"的 Warp，但本质都是用线程级并行覆盖访存延迟。

## 5. Block 到 Warp 的映射

程序员写 CUDA 代码时关心的是 [[Block]]（线程块）和线程数，例如 `<<<nBlk, nThr>>>`：

- 软件层：程序员定义 Block 和 Thread；
- 硬件层：编译器与驱动自动把 Block 拆分为 Warp。

例如 3 个 Block、每 Block 100 线程，则 Block0 拆成 4 个 Warp（线程 0–31、32–63、64–95、96–99）。程序员不需要知道 Warp 边界。

## 6. 分支分歧与 Warp 重组

SPMD 中各线程可能走不同分支（如 if 条件），导致同一 Warp 内出现分歧，SIMD 利用率下降。硬件可以动态地把执行相同路径的线程重组成新 Warp，重新对齐，提高 SIMD 利用率——这也是 SIMT 相对传统 SIMD 的一个灵活性来源。

## 7. 实例：GeForce GTX285

- 30 个 Core，每个 Core 是 8-way SIMD 功能单元（8 个 Lane）；
- 通过 FGMT 交织 32 个 Warp，每个 Warp 32 线程；
- 理论同时执行线程数：30 × 32 × 32 = **30720**。

这就是 GPU "大力出奇迹" 的典型路径：单核极简、靠数量堆并行，靠调度隐藏延迟。

## 关键概念速查

- [[SIMD]]：单指令多数据，编程与执行一体；
- [[SPMD]]：单程序多数据，编程模型；
- [[SIMT]]：单指令多线程，GPU 的执行模型；
- [[Warp]]：GPU 硬件调度的基本单位（典型 32 线程）；
- [[FGMT]]：细粒度多线程，每周期切换 Warp 隐藏延迟；
- [[Block]]：CUDA 编程中的线程块，由硬件自动拆分为 Warp。
