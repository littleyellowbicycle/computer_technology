# C++高性能计算优化实战心得

## 核心结论
> 高性能计算的核心是在精度、速度和存储三者间做权衡：牺牲精度与查表插值是最直接的提速手段，但需警惕误差累积（如椭圆渲染瑕疵案例）。数学恒等变换（如 [[幂函数]] 改写为 exp(n·log(x))）和查表插值能带来数倍性能提升，而看似精妙的浮点位操作（如指数位调整实现乘除 2^n）反而不如直接乘法，因为编译器已做指令级优化。

## 详细内容
## 核心原则

作者通过"抛开需求谈误差就是耍流氓"的段子总结了三条提速哲学：

1. **牺牲精度换速度**：图像处理等领域天生容许 [[有损计算]]，jpeg 等有损压缩已是先例。
2. **查表（LUT）最粗暴**：记录大脑缓存中的常数（如 16×16=256），省去运行时计算。
3. **查表+插值拟合**：以存储换速度，是又快又不准但仍可控的方案。

## 数学恒等变换

简单代数改写往往能换来显著加速，例如：

- `15×17 = (16-1)×(16+1) = 16² - 1 = 255`，把乘法转化为查表减法。
- [[幂函数]] `pow(x, n)` 改写为 `exp(n·log(x))`，10 亿次运算从 21499ms 降到 13089ms。
- [[双曲正弦]] `sinh(a)` 改写为 `(expf(a) - 1/expf(a)) * 0.5f`，10 亿次从 35907ms 降到 9166ms。

⚠️ 并非所有变换都有效：`pow(x,n) = exp2(n·log2(x))` 反而耗时飙升至 134260ms，因为 `exp2f/log2f` 的实现路径更慢。

## 自定义数学库 zmath

作者用宏统一封装了一套 [[数学函数库]] `zmath`，对每个标准库函数提供三档实现：`fast_*`（查表+插值，极快但有损）、`quick_*`（多项式/牛顿迭代，精度较高）、`::std::*`（标准库实现）。

```cpp
#define Z_CBRT zmath::fast_cuberoot   // or zmath::quick_cuberoot or ::cbrtf
#define Z_SIN  zmath::fast_sin         // or zmath::quick_sin  or ::sinf
```

## 立方根优化案例

以 [[立方根]] 函数为例（10 亿次耗时对比）：

| 实现方式 | 耗时 (ms) | 精度 |
|---------|----------|------|
| `::cbrtf(x)` | 32721 | 标准 |
| `::powf(x, 1/3.0)` | 21263 | 略损 |
| `zmath::quick_cuberoot`（Newton-Raphson） | 4358 | 4e-6 起 |
| `zmath::fast_cuberoot`（查表+插值） | **4115** | 4e-5 起 |

`fast_cuberoot` 的核心思路：用 `cbrt(x) == 5·cbrt(x/125) == 0.2·cbrt(x·125)` 把任意输入映射到 `[8, 1000)`，再在 2048 项预生成的 [[查找表]] 中做线性插值。

⚠️ 即便是 0.00004 的误差，在多次叠加后也会暴露：作者在生成椭圆图像时，引入 `quick_cuberoot` 导致像素出现明显瑕疵。

## 浮点位操作的"优化了个寂寞"

理论上，把浮点数乘除 2^n 改为调整指数位的加减运算应该更快：

```cpp
// 通过修改 IEEE-754 的阶码位实现乘除 2^n
k.iVal = (k.iVal & 0x807fffff) | ((((k.iVal >> 23) + n) & 0xff) << 23);
```

实际测试中：

| 实现 | 10 亿次耗时 |
|------|------------|
| `::ldexpf` | 21300ms |
| `::scalbnf` | 7661ms |
| `fast_shift` | 1694ms |
| `z / 32768.0f`（直接除法） | **753ms** |

直接写 `z / 32768.0f` 反而最快——现代 [[编译器优化]] 早已把这种模式识别为位操作，再手动写等于徒劳。

## 实战建议

- **优先用宏切换实现**：在 [[性能剖析]] 的数据基础上选择 fast/quick/std 三档。
- **误差需量化报告**：明确给出误差区间（"x∈[100, 1000] 误差小于 8e-6"），匹配业务容差。
- **善用查表+插值**：对高度重复的纯函数（三角、对数、开方）是性价比最高的方案。
- **参考 [math-parser-benchmark-project](https://github.com/ArashPartow/math-parser-benchmark-project)**：比较 11 种 [[数学表达式解析]] 引擎的吞吐。
