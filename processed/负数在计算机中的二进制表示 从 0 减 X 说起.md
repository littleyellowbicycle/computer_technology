# 负数在计算机中的二进制表示:从 0 减 X 说起

## 核心结论
> 计算机中存放的「负数」本质上是固定位宽下做 0 - X 的二进制减法结果,借位被丢弃,这与所谓的「补码」只是同一事物的不同命名。由于这种表示天然满足模运算,加法器无需区分正负号就能正确处理加减混合运算。

## 详细内容
## 核心结论

- 「补码」是计算机专家给出的一个概念名称;实际操作中,-X 在 8 位机里就是 0 - X 的二进制结果,高位借位被自动忽略。
- 这种表示之所以有效,是因为 [[补码 表示法]] 本质上就是以位宽为模的 [[模运算]] 下的加法逆元,加法器因此可以无差别地处理正负数。

## 正文

### 1. 去掉概念包袱:直接做 0 - X

在 [[八位机]] 中,0 的二进制就是 `0000 0000`。要表示 -1,直接做:

```
  0000 0000
- 0000 0001
= 1111 1111  (借位忽略)
```

得到的 `1111 1111`(十进制 255)就是「-1 在机内的样子」。同理,-2、-3 都是从 0 出发一次次减下去,呈现出从 255、254、253 一路递减的规律。

由此可以归纳出一个朴素的规则:
- 正数 X:机内就是 X 本身的二进制。
- 负数 -X:机内就是 0 - X 的二进制结果(以位宽为模,自动环绕)。

### 2. 为什么这种「0000 减 X」恰好等于补码?

设机器位宽为 $2^n$,则 0 - X 等价于 $2^n - X$ 再取低 n 位。而数学上的 [[补码]] 定义恰好是「模 $2^n$ 下的加法逆元」,即满足 X + (-X) ≡ 0 (mod $2^n$) 的那个值,正好等于 $2^n - X$。所以两套说法描述的是同一批比特位,只是命名角度不同。

### 3. 好处:加法器不用区别正负

既然表示层已经统一,硬件实现就非常省事——任何 a + b 都做无符号加法,溢出位丢掉即可自动正确。例如 80 - 31:

```
  0101 0000   (+80)
+ 1110 0001   (-31,即 0-31 的结果)
= 1 0011 0001
  0011 0001   (= 49,进位丢弃)
```

这一行加法的正确性,正是源于 [[补码 表示法]] 与无符号加法的等价性。

### 4. 视角切换:自己起名也无妨

原文作者的态度很尖锐:既然机内的数值可以由「0 - X」直接算出,那「原码/反码/补码」就只是一套术语,你可以换成「龙虎码」「太极码」之类的名字。只要说出「在 n 位机中,正数是它自己,负数是 0 减它」这套规则,逻辑上完全自洽。
- 在教学层面:术语是为了精确沟通,补码是行业标准命名。
- 在理解层面:抓住「位宽为模的减法」这个本质,比背诵「符号位不变、取反加一」更直接。
