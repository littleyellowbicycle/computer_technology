# 增加内存为何无法提升CPU性能——Windows内存压缩的隐性开销

## 核心结论
> 理论上增加内存可解除CPU的内存压缩负担，但Windows即使在内存充裕时仍默认启用内存压缩，导致CPU资源被无谓消耗。禁用内存压缩后CPU性能可获得10%到1000%的提升，具体收益与内存容量、CPU频率和负载类型强相关，需结合benchmark权衡。

## 详细内容
## 背景与现象

升级[[内存条]]后理论上CPU应被解放，因为无需再为内存压缩付出周期。然而实际体验中CPU性能几乎没有变化，根因在于[[Windows]]的[[内存压缩]]机制具有过度防御特性——即使物理内存远未耗尽，压缩进程仍持续运行，把数据无意义地反复压缩与解压。

参考issue：Windows-Dev-Performance#35（微软已承认该行为在最新Win11上仍可复现，64GB内存、空闲状态下4GB数据被压缩到1GB）。

## 核心机制：MMAgent的两大可调开关

Windows通过MMAgent模块管理两个会消耗CPU的内存策略：

1. 内存压缩（MemoryCompression）
   - 默认开启，把热点页面压缩存放以节省内存。
   - 代价是CPU周期被压缩和解压占用。
   - 禁用命令（管理员PowerShell）：Disable-MMAgent -MemoryCompression，重启生效。

2. 内存分页合并（Page Combining）
   - 默认开启，合并相同内容的内存分页以节约空间。
   - 代价是周期性扫描内存分页，消耗CPU并增加[[内存带宽]]开销。
   - 关闭后内存占用会显著上升，对个人PC通常得不偿失。

## 性能收益与适用场景

禁用内存压缩后的CPU提升幅度差异极大，源于内存越大、CPU越弱时基线压缩开销占比越高：

- 典型场景：10%到数百%的提升。
- 极端场景：低频CPU（限制到最低频率的笔记本节能模式）搭配大内存（128GB）跑4K读写，测出过约1000%的提升。
- 反例：小容量低频内存搭配强CPU组合下，禁用压缩会导致[[内存带宽]]和[[页面交换]]压力上升，性能反而下降。

## 调优建议

- 没有爆内存风险的用户可关闭内存压缩，以释放CPU。
- TB级内存的服务器在特定负载下也可考虑关闭分页合并。
- 任何调优前都应做对照[[基准测试]]，因为平衡的艺术是性能调优的永恒主题。

## 一句话总结

内存容量与CPU性能不是线性关系，关键在操作系统是否仍在做没必要的事——把内存压缩关掉，让CPU回到真正该干的计算上。
